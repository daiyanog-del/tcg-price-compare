# 一人回し スマホ最適化 設計計画（2026-09-02 計画／2026-09-03 フェーズ1 実装）

> 状態: **フェーズ1 実装完了（2026-09-03・§9 参照）。ユーザー実機検収待ち。フェーズ2/3 は未着手**。
> 参考: https://duel-simulator.miyauchidp.dev/ （比較観察済み。目標は模倣ではなく差別化）

## 0. 目的と物差し

- 目的: スマホだけで「展開を組み立てて記録・共有する」作業が、迷わず・誤操作なく完結すること
- 検収の物差し（フェーズ3完了時）:
  「デッキ読込 → 特定の2枚を手札へ → 3枚を盤面へ展開 → 1枚を墓地へ → 共有リンク発行」を、
  スマホ実機で**誤って別カードを動かすことなく**完走できる
- 主用途の前提（ユーザー提示）: ランダム5ドローより「特定の手札1〜2枚から始めて展開を記録・共有」が多い。
  → 5ドロー/1ドローは主役から外し、メニュー内に残す

## 3. 設計

### 3.1 レイアウト（縦1カラム・≤767px のみ適用）

```
┌ 上部: 選択カードの詳細（選択時のみ・折りたたみ可）┐
│ 盤面 6列 × 3段（EXゾーン2・モンスター6・魔法罠6）    │  ← 墓地/除外を右から外す
│ 手札（横スクロール・常時表示・枚数バッジ）           │
│ 墓地（横スクロール）│ 除外（横スクロール）            │  ← 常時表示（ユーザー要望）
│ EXデッキ（横スクロール・常時表示）                   │
├ 下部固定バー: [デッキ 35] [取消] [共有] [⋯メニュー] ┤  ← デッキ列は廃止しボタン化
└──────────────────────────────────────────────┘
```

- カード幅の試算（gap は solitaire-brand.css の 10px を採用）:
  - 6列基準: (375 − 左右8 − gap50) / 6 ≒ **52px**（現行比 +33%）
  - gap を 6px に詰める案: (375 − 8 − 30) / 6 ≒ **56px**（+44%）。密集感が増すので実機で判断
- **縦スクロールなしで収める（ユーザー決定 2026-09-02）**。設計上の高さ予算は **innerHeight 660px**
  （iPhone Safari でアドレスバー等が出た状態の実測相当。Android Chrome は≈780で余裕）。
  ラベルを §3.6 の縦タブ方式にした場合の予算（52px・カード高 75px）:

  | 段 | 高さ |
  |---|---|
  | 盤面 3段（75×3＋gap 10×2＋余白 8） | 253 |
  | 手札（75＋枠・余白 10） | 85 |
  | 墓地｜除外（同上） | 85 |
  | EXデッキ（同上） | 85 |
  | 下部固定バー | 52 |
  | **合計** | **560** |

  （相手の想定妨害トレイはメニューへ移す決定のため盤面上の 28px は不要）
  660 に対し 100px の余裕。余裕は盤面側に回さず、端末差（Safari の下部バー出没）の吸収に充てる。
  収まらない端末（innerHeight < 600）では **カード幅を 660 基準で縮める**（幅計算に高さ制約を残す。
  現行 `correctSlotWidthByMeasurement` の縮小ロジックはそのまま使える）。ページの縦スクロールは発生させない
- 墓地｜除外の行（左右2分割は決定済み）。「3枚しか見えない」の解消案:
  - 各半分の可視幅 = (375 − 8 − gap 10) / 2 − 縦タブ 16 ≒ **162px**。52px カードを並べると 2.8 枚。これが「3枚」の根拠
  - 案a-1（推奨）: **重ね表示（ファン）**。先頭は全幅、以降は 28px ずつずらして重ねる → **5枚**が見える。
    横スクロールで残りも見える。重ねたカードもタップ選択できる（§3.2 の触れた瞬間の持ち上げで、どれを掴んだか分かる）
  - 案a-2: 墓地/除外だけ **0.75 倍（39px）** で並べる → 4枚。小さくなるので見やすさの目的と相反
  - 案a-3: **タップで全幅展開**。墓地の縦タブをタップすると墓地が行全幅（343px）に広がり除外は枚数チップに畳まれる。
    a-1 と併用可能。実装は小さい（クラス切替）ので **a-1 ＋ a-3 の併用**を推奨
  - 案b（不採用）: 墓地｜除外｜EX の3分割。1列 110px で 2枚しか見えない
- 幅計算（main.js `fitFieldToViewport`）はスマホ縦向きの分岐を「6列・サイド無し」に書き換える。
  `correctSlotWidthByMeasurement` の「収まらなければ縮小」は、スマホでは**縦スクロール許容のため無効化**（縮小すると見やすさの目的と矛盾）

### 3.2 タップ操作と「今どのカードを触っているか」の明示

誤操作の根治はここ。3層で示す。

1. **触れた瞬間（touchstart）**: そのカードを持ち上げる（scale 1.15・光る枠・影）＋**指の真上にカード名ラベル**を出す。
   まだ移動はしない（8px 移動でドラッグ開始、という現行ロジックはそのまま）
2. **タップで離した（移動なし）**: そのカードを**選択状態**として固定（枠は点灯したまま）。
   置ける先（盤面スロット・手札・墓地・除外・デッキ）が淡く点滅。行き先をタップで移動。
   同じカードを再タップ／空き地タップで解除
3. **選択中のアクションシート**（画面下部・下部バーの上に重ねる）:
   `守備表示｜セット｜墓地へ｜除外へ｜デッキに戻す｜効果発動`。長押しメニュー（500ms）は残すが、主導線はこちら
4. **詳細パネル**: 選択と同時に上部へ「大きめ画像＋カード名＋種別＋効果テキスト＋ATK/DEF」を出す。
   `card-info-panel.js` の `_renderCard` をそのまま流用（価格行は非表示）。「×」で閉じられ、閉じた状態は記憶
5. **ドラッグ中**: 現行の scale 1.12 に加えてカード名ラベルを付ける。落とし判定（周囲20px補完）は維持

移動は**必ず既存の `executeDrop` を通す**（リプレイ記録の唯一の経路）。タップ移動用の別経路を作らない。

### 3.3 デッキ一覧シート（特定カードを手に取る導線）

- 下部バーの「デッキ 35」を押すと全画面ボトムシート:
  5列グリッド（カード幅≈66px）／上部に名前検索（部分一致）／タップで複数選択→「手札へ (2)」／個別長押しで「盤面へ」
- EXデッキは常時表示の行があるので、シートは不要（行内の横スクロールで足りる）
- 「シャッフルして1ドロー」「リセット&5ドロー」はシート内の副ボタンに置く
- 参考サイトに対する最もわかりやすい差別化ポイント

### 3.4 記録・共有をスマホで完結

- 手数0: 下部バーは `[デッキ] [⋯]` のみ。手数1以上で `[取消] [共有]` が現れる（再生・スライダーはメニュー内）
- 共有: 1枚のシートに「タイトル」「コメント」「共有リンクをコピー」「Xに投稿」「JSON保存」をまとめる。
  responsive.css の非表示指定（`#replayShare` 等）を撤去し、この共有シートへ付け替える
- 保存経路（`/api/solitaire/replay`・60秒10回）は現行のまま

### 3.5 初見の導線（小）

- デッキ未読込時は盤面中央に「デッキを読み込む」の大ボタン → デッキ選択シート（現在の左サイドバーの中身をボトムシート化）
- 画面端の「▶◀」はスマホでは廃止（左＝デッキ選択シート、右＝メニューへ吸収）
- 相手の想定妨害トレイは **スマホでは盤面上から外し、下部バーの「⋯メニュー」内の項目「相手の想定妨害」からシートとして開く**（決定 2026-09-02）。
  トレイに妨害が置かれているときは、メニューボタンに枚数バッジを出して存在を示す

### 3.6 エリア名称（手札・墓地・除外・EX・デッキ）の置き方

現状: 各エリアの上に独立行でラベル（font 0.68rem ＋ margin 4px ＋ エリア内 padding）→ **1エリアあたり約 25〜30px** を消費。
スマホでは手札・墓地・除外・EX・デッキの5箇所で **合計 ≈125px**（画面の 15%）がラベル行に取られている。
さらに盤面のゾーンには名称が無く、逆にラベルの必要性が低いエリアほど行を消費している。

選択肢:

| 案 | 内容 | 縦の節約 | 横の犠牲 | 欠点 |
|---|---|---|---|---|
| L-1（推奨） | **左端の縦タブ**。エリアの左辺に 16px 幅の帯を置き、縦書き（`writing-mode: vertical-rl`）で「墓地 7」。カードは帯の右から並ぶ | 約 25px × 4段 ＝ **100px** | 各段 16px（横スクロール領域なので実害なし） | 縦書きは一瞬読みにくい。枚数は数字だけ横向きに置く |
| L-2 | **左上の重ねバッジ**。エリア内左上に半透明の小バッジ「墓地 7」を absolute で重ねる | 同 100px | なし | カードが増えると1枚目の左上を隠す。手札は常に先頭カードと重なる |
| L-3 | **ラベル廃止・色と位置で識別**。墓地＝赤系の枠、除外＝灰系、手札＝青系、枚数チップだけ右上 | 同 100px ＋ α | なし | 初見で判別できない。参考サイトも色分けはしているがラベル併用 |

L-1 を推奨。理由: 枚数が常に見える（「今何があるか」のニーズ）、カードを隠さない、枠色（L-3）は L-1 の補助として併用できる。
盤面ゾーンには従来どおり名称を付けない（ゾーンアイコンの透かしで足りる）。
デッキは行を廃止して下部バーのボタン「デッキ 35」になるためラベル問題は消える。

節約した ≈100px は §3.1 の 660px 予算の内訳に既に織り込み済み（各段 85px はこの方式が前提）。

## 8. フェーズ1 実装仕様（確認用・1枚）

対象: ≤767px かつ縦向き。PC・横向きスマホは一切変更しない。

### 8.1 DOM とレイアウト

- `templates/solitaire.html` は **墓地/除外の DOM を移動しない**。スマホでは `.main-content` を `display: contents` にして
  `.custom-layout`（盤面）と `.side-slots-container`（墓地/除外）を `.sol-field-area` の直接の flex 子にし、`order` で
  「盤面 → 手札行 → 墓地｜除外 → EX → （デッキ行は非表示）」に並べる。`display: contents` が既存 JS の
  `offsetHeight` 計測（`fitFieldToViewport` の `--field-height`）に影響しないことを最初に確認する（影響すれば新コンテナ方式へ切替）
- `.center-row` は手札と EX を横並びにしている。スマホでは `flex-direction: column` にして手札行・EX行に分ける
- `#imagePool`（デッキ行）は `display: none`。デッキの実体（`#poolRow` の子要素）は残す＝既存のドロー処理・リプレイ処理を変えない
- 下部固定バー `#solMobileBar`（新規・`position: fixed; bottom: 0; height: 52px`）: `[デッキ N] [取消] [共有] [⋯]`。
  フェーズ1では「デッキ N」は既存の 1ドロー相当の仮動作（タップで1枚ドロー）にし、一覧シートはフェーズ2。
  「共有」はフェーズ3まで非表示。「⋯」は `盤面セーブ／盤面ロード／リセット&5ドロー／コイン／ダイス／相手の想定妨害／操作方法／フィードバック` の簡易メニュー
- 左右パネル（`#solSidebar` `#solRightPanel`）と端の `▶◀` はスマホで `display: none`。デッキ選択は「⋯」内「デッキを読み込む」→
  左サイドバーの中身（`#deckInputContainer`）をそのままボトムシートに **移動せず再親付けもせず**、シートの中に `position: fixed` で表示する
  （既存 JS の ID 参照を壊さない）
- 縦タブ（§3.6）: `.pool-label` / `.sol-hand-area .pool-label` / `.sol-side-area .pool-label` を `writing-mode: vertical-rl; width: 16px` にし、
  親を `flex-direction: row` に。枚数バッジは既存のゾーン枚数バッジ（solitaire-brand.css 1495 行付近）を縦タブ内に寄せる
- 墓地｜除外の重ね表示: `.side-slot` 内のカードラッパーに `margin-left: calc(-1 * (var(--slot-width) - 28px))`（2枚目以降）。
  縦タブタップで `.sol-side-area.expanded` を付け、片方を `flex: 1`、もう片方を幅 40px の枚数チップにする

### 8.2 幅計算（main.js）

- `fitFieldToViewport` のスマホ縦向き分岐: `slotW_w = floor((availW − 8 − 50) / 6)`（6列・サイド無し）。
  高さ側は `slotW_h = floor((innerHeight − 固定分) / 8.7)`。
  8.7 の根拠: カード高 = 1.45 slot、縦に並ぶカード段は 盤面3段＋手札＋墓地除外＋EX の 6 段 → 6 × 1.45 = 8.7。
  固定分 = 下部バー 52 ＋ 各行の枠・余白 10×3 ＋ 盤面余白 8 ＋ 盤面 gap 20 ＝ 110px。
  検算: innerHeight 660 → (660−110)/8.7 ≒ 63px。幅側 52px の方が小さいので幅が支配（＝縦は収まる）。**縦スクロールを出さない**ため高さ制約は残す
- `correctSlotWidthByMeasurement` はそのまま使う（収まらなければ縮小）。基準は `.sol-field-area` の下端が「innerHeight − 下部バー 52」を超えないこと
- `--gap` はスマホで 10px のまま（56px 案は実機確認後）

### 8.3 タップ操作の状態機械（drag-drop.js に追加・`executeDrop` は変更しない）

```
idle ──touchstart(card)──▶ pressed   ：カードに .touching（scale1.15・光る枠・影）＋ 名前ラベル(指の上 40px)
pressed ──move ≥8px──▶ dragging     ：既存のドラッグ処理（ラベルは追従）
pressed ──touchend(移動なし)──▶ selected ：.touching を外し .selected を付ける。置ける先に .drop-hint（淡い点滅）。
                                         詳細パネル(§3.2-4)を上部に表示。アクションシートを下部バーの上に表示
pressed ──500ms 静止──▶ (現行の長押しメニュー。selected へは遷移しない)
selected ──tap(置ける先)──▶ idle      ：executeDrop(選択カード情報, 行き先情報, 行き先要素, {}) を呼ぶ
selected ──tap(同じカード / 空き地)──▶ idle ：解除
selected ──touchstart(別カード)──▶ pressed(別カード) ：選択の付け替え
selected ──アクションシートの項目──▶ idle ：既存のコンテキストメニュー関数（守備/セット/デッキに戻す等）を呼ぶ
```

- 「置ける先」の判定は既存 `getDropZoneInfo` を流用（判定を二重に持たない）
- 選択カードの情報は `getDraggedElementInfo(ev.target)` の戻り値をそのまま保持する
- 名前ラベルの文字列は `img.tier-item` の `alt`／プロキシは `.proxy-name` から取る（既存の名前解決を使う）
- ダブルタップ効果発動（`dblclick`）はタッチではアクションシートの「効果発動」に置き換える

### 8.4 詳細パネル（スマホ）

- `card-info-panel.js` の `_renderCard` / `_showUnknown` を再利用し、`#solMobileCip`（新規・盤面の上に `position: fixed; top: 0`・高さ最大 160px・横並び: 画像 100px ＋ 名前/種別/効果テキストのスクロール）へ描画
- 価格行（`priceData`）はスマホでは描画しない（引数を `null` で渡す）
- 「×」で閉じ、閉じた状態は `localStorage`（キー `sol_mobile_cip_hidden`）に記憶。閉じている間は名前だけを下部バーの上に 1 行で出す
