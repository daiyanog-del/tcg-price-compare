## 2026-08-03: ページ送り欠如の解消（第6弾・カードラボ販売＋カードラッシュ買取）
- **決定**: 1ページ目しか取っていなかった残り2経路にページ送りを実装（いずれも `max_pages=5`）
  - **カードラボ販売 `scrape_clabo`**: 1ページ60件が上限。パース部を `_parse_clabo_items()` に切り出し、ページ送りループを追加。終端検出は3条件（①ページャ `div.pager` の `page=N` 最大値 ②60件未満 ③全商品が既出）
  - **カードラッシュ買取 `scrape_cardrush_buy`**: 1ページ100件が上限。パース部を `_parse_cardrush_buy_items()` に切り出し。終端は `props.pageProps.lastPage`（保険として空配列・100件未満も見る）

## 2026-08-03: 検索語正規化の不揃いを是正（第4弾・空白圧縮＋コロン除去を共通化）
- **決定**:
  - `_squeeze_spaces()`（`re.sub(r"\s+"," ").strip()`）を新設し、`_normalize_search_query` と `_cardrush_search_query` の両方の末尾で使う。従来はカードラッシュ専用関数にだけ埋まっていた

## 2026-08-03: 検索キャッシュを店舗束形式へ（第3弾・キャッシュ汚染＋失敗0件固定の根治）
- **背景**: 第1弾・第2弾デプロイ後もユーザーから「在庫があるのにヒットしない」報告（14ペア）。本番で全ペアの fresh 検索はヒットすることを確認し、真因は**キャッシュの構造欠陥**と特定した。キー=カード名のみで「どの店舗を調べた結果か」を記録しないため、①店舗を絞った検索が全体キャッシュを上書きし、以後15分間ほかの店舗が「0件 (cached)」になる（本番で実証。同カードを店舗切替で検証する操作＝今回の報告リスト作成手順そのものが100%踏む）②取得失敗による0件も「在庫なし」として15分固定（カードラボ403多発と相乗）
- **決定**:
  - **キャッシュを店舗束形式に変更**: `{"shops": {店舗名: {timestamp, partial, results}}}`。1カード1ファイルは維持し、店舗ごとに独立TTL（15分）。旧形式ファイルは全店ミス扱い（デプロイでキャッシュは消えるため実質影響なし）
  - **不足店舗だけスクレイプしてマージ**: `cache_get_shops`/`cache_store_shops`（買取版も同型、共通ヘルパーに委譲）。「調べて0件」と「調べていない」を区別する
  - **取得失敗店舗はキャッシュしない**: 例外 or fetch_errors>0（`run_shop_with_status` で判定）の店は書かない＝次回再試行。検出できるのはネットワーク層の失敗のみで、店舗サイトの構造変更由来の「例外なし0件」は従来どおりキャッシュされる（限界として明記）
  - **デッキ検索の結果に partial 印**: /api/deck はトレコロ・カーナベルが1ページ目限定のため、その2店の保存に partial=true を付け、通常検索(/api/search)は partial を不足扱いで完全版を取り直す（従来は不完全結果が通常検索に15分流用されていた既存劣化も同時に解消）
  - price_history への即時 upsert は「今回スクレイプした行のみ」渡す（キャッシュ命中分は再送しない）。/api/deck の ignore_duplicates=True は維持
- **影響範囲**: scraper.py キャッシュ節・app.py 4経路（販売/買取×検索/デッキ）のみ。collect_prices/collect_buyback は compare_prices 経由でキャッシュ不使用のため無影響。SSE契約はフロント実装と突合して維持（UIの「(cache)」バッジは既存実装がそのまま機能）
- **検証**: pytest 226件全緑（新規 test_cache_coverage.py 13件＋test_search_route_cache.py 3件）。ローカルFlask実機で①店舗絞り→別店舗の汚染解消 ②失敗店舗の非キャッシュ・再試行 ③partial→通常検索で完全版取り直し ④UI混在ストリーム正常（(cache)バッジ・表描画・コンソールエラーなし）。reviewer監査1巡（高指摘0・中3件=ルートテスト追加/コメント精密化/max_workersガード、すべて反映）
- **バックログ化した指摘（reviewer低）**: グローバルロック内のJSON parse（カード単位ロック化で解消可）／ページ送り途中失敗の部分結果を全捨てせず partial 保存する案。TASKS.md 参照
