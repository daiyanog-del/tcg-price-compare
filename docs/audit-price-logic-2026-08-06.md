## 判明した価格提供経路の全体像

- 価格を返す経路は20系統（詳細は本監査のセッション記録）。「前日比%」の計算実装が**5系統並存**（S1=RPC販売 / S2=RPC買取 / S3=x_poster.get_price_movers / S4=notify.compute_drop / S5=aggregations経由 /api/wish-prices）
- ガード（共通店舗・同方向2店・¥10以下除外・(不明)除外）の適用が経路ごとにバラバラ

## 発見一覧（重要度順）

### F1 🔴実証済み: カード詳細グラフが人気カードで6週間欠けている（1000行上限・3例目）
- 場所: `app.py:1288-1294`（/api/price-history）。`.limit(2000)` だが PostgREST 上限1000で切られ、昇順のため**新しい側が欠落**
- 本番実測: 「墓穴の指名者」= ちょうど1000行・最終日 **2026-06-23**（実施日8/6の6週間前）
- 影響: 90日で1000行を超えるカード **335枚**（最大3,345行）。一人回しのカード情報パネル「最新最安値」も同APIのため**6月の価格を表示**
- tracked_cards(7月)→estimate_cache(8月)に続く同一クラス3例目

### F2 🔴静的確認: X投稿グラフの読み出しも同クラス（4例目）
- 場所: `featured_pack.py:242-247`（get_card_history_since）。limit/rangeとも無し（既定1000行キャップ）
- `x_poster.py:995` → chart_renderer 経由でX投稿画像に使用

### F3 🟠実証済み: デッキ見積もりの正体は「7日間の底値の合計」
- RPC `get_card_best_prices` の定義は**リポジトリに無く本番DBのみ**に存在。取得した定義: 7日窓の全店舗・全レアリティ・全日付から `DISTINCT ON (card_name) ... ORDER BY min_price ASC`（最安1行）
- 実測: 2,690枚中 **1,632枚(61%)** は3日以上前の観測値が「現在の最安」として合計に載る → **見積もりは系統的に安値へ偏る**
- ¥10以下ガード無し（現データでは該当0）・(不明)レアリティ除外無し（該当6枚）
- 意図した仕様かどうかの記録がどこにも無い（要裁定）

### F4 🟠実証済み: 新弾X投稿（post_featured_movers）はガード済みロジックとほぼ無相関
- S3（`x_poster.py:41-117`）: レアリティ横断のカード単位min・ガード①②無し・**fallback=True で閾値未満でも必ず1枚投稿**
- 8/5→8/6の実測: S3の±¥50以上の候補**42件のうち、ガード済みS1が確認したもの0件**。逆にS1の実変動48件中**18件はS3では不可視**
- レアリティ横断minは「どのレアリティが最安か」の入れ替わりを価格変動として検出する統計量であり、7月に偽陽性98%と確定した構造そのもの。post-featured は schedule 現役

### F5 🟠実証済み: 購入候補の±%表示は約16%が共通店舗で消える偽シグナル
- S5（/api/wish-prices）は8日窓の最古日vs最新日・全店舗min・ガード無し
- 標本668カード（25%ハッシュ標本）: drop信号25件中 **4件(16%)は共通店舗で再計算すると消滅**（4件とも横ばい以上＝符号逆転）

### F6 🟡実証済み: まとめ買い店舗合計に7日前の古値が5.8%混入
- /api/wish-shop-totals は7日窓の日付を潰したmin。12,487(card,shop)ペア中 **723(5.8%)が最新日より安い古値**を採用、その平均乖離**26%**

### F7 🟡静的確認: Web Push通知（notify.py）は死んでいる
- 呼び出しは collect-prices.yml のみで、その schedule はコメントアウト済み（Render Cron移行）。Render cron側に notify 実行は無い
- docstring「7日前比」vs実装「最大8日窓」の既知不一致も未修正のまま残置

### F8 🟡静的確認: ページ分割取得2箇所で並び順指定漏れ
- `app.py:1779`（wish-shop-totals）・`app.py:1942`（card-rarities）は range分割に `.order()` 無し。ページ境界の取りこぼし理論リスク。自前ヘルパ `_fetch_all_rows`（collect_prices.py:101）の docstring 警告に自ら違反

### F9 🟡表示不整合: カード詳細のグラフは「店舗平均」・最安表示は「min」
- `templates/index.html:3530-3535` がレアリティ×日付で全店舗平均を描画。同一画面の最安値表示（min）と統計量が異なる。ユーザーへの説明も無い

### F10 🟠効率（実測）: 夜間収集の時間の多くがエラーに費やされている
- 販売収集は**毎晩175〜280分（約3時間）**。8/5の内訳: **カードラボ error 1,639/2,723件(60%)**・**カードラッシュ error 666件(24%)**
- 買取収集: カードラボ empty 309/462件(67%)は他店比で異常水準（要因未特定）
- 403打ち切り実装(8/3)後もカードラボの誤差時間・欠測が支配的。`&num=120` 化・カタログ巡回案（TASKS.md既載）の優先度を上げる材料
